
## Geral

- A estrutura do projeto poderia ser melhor. Os Usecases e Service estão largados, assim como as informações do Banco de Dados.

- A classe _Base não deve ser implementada já que é apenas uma referência de atributos. Portanto, ela deve ser mudada para **interface**, ou pelo menos **classe abstrata**.

- Colocar o DTO de criação dentro de uma pastas de DTO's ajudaria. Padronizar os nomes. (Provavelmente serão criados outros DTOs apenas com os dados necessários para a requisição específica, não retornar a classe completa).

## Poucas Etapas

O endpoint esta chamando diretamente o serviço. Seria interessante se ele chamasse um Controller ou UseCases no lugar. No meio dessas etapas podem ser adicionadas mais tratativas e regras de negócio.

## Error Handling

O código tem poucas tratativas de erro no geral.

Aqui o handler de erro está ruim, é bom adicionar uma justificativa do por que o erro ocorre.
```
if(request.Name.Count() < 5)
    return null;
```

O ```request.Status``` é 'dead'ou 'alive', mas dentro da aplicação não tem nenhum controle sobre esses valores. Talvez criar um Enum de estados seria interessante.

Para resolver a questão de tratativa de erro, deve ser criada um objeto de Ação que além de entregar o retorno, informa "Sucesso" e "Fracasso".

Dessa forma, o erro não irá quebrar a aplicação.

```
public static Response<T> Ok(T value) 
    => new Response<T>(string.Empty, true, value);

public static Response<T> Fail(string message) 
    => new Response<T>(message, false, default);
```
