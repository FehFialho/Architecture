## Por que retornar entidades diretamente em uma API pode causar problemas?

Porque dessa forma não esta sendo realizada uma tratativa, seja ela de dados nulos ou errados. Os dados não serão processados antes de serem entregues, podendo gerar imprevistos ou confusões. O mais correto seria criar um meio termo (Como UseCase/Handler) para fazer o tratamento do dado antes de passar o mesmo para a camada superior.

## O que significa dizer que uma classe possui baixa coesão?

Significa que as funcionalidades presentes na classe não fazem tanto sentido juntas e poderiam ser divididas ou resumidas.

## Por que interfaces muito grandes podem causar problemas?

Porque o usuário será obrigado a aplicar métodos que podem nem ser utilizados no futuro, causando confusão, perda de tempo, etc. É melhor que as interfaces sejam divididas entre si.

## Em qual camada um UseCase deve ficar e por quê?

Os UseCases devem ficar na camada de aplicação, pois é lá onde é orquestrado o fluxo do sistema. Também é onde as regras de negócio são definidas.

## Qual o principal problema de acessar:
```cs
A.B.C.D
```
Idealmente um método deve saber o mínimo possível dos demais. Além de questão de encapsulamento, caso o método interno mude, o principal terá mais dificuldade para ser adaptado. O ideal é seguir a Lei de Demeter.

## Qual o principal objetivo de dividir uma aplicação em camadas?

Facilitar a expansão e manutenção do sistema, já que conforme ele vai crescendo, se torna mais difícil realizar mudanças e se adentrar no projeto do 0. 

Com a organização em camadas, podemos compreender o projeto de forma muito mais rápida e prática, além de realizar mudanças de forma mais fácil pois menos partes do código precisaram ser alteradas devido ao baixo acoplamento.

## Qual a responsabilidade da camada Application?

A camada Apllication é a responsável de orquestrar o fluxo do sistema. É ela que vai cuidar das permissões e fazer a integração dos serviços do sistema por meio da camada de Infrastructure.

## Qual a responsabilidade da camada Domain?

A camada Domain é onde ficam as Interfaces e Modelos utilizados na aplicação. É muito importante pois define a estrutura e até onde o escopo do projeto vai. Ela também é responsável pelo Service, que será utilizado pela Infrascture.
